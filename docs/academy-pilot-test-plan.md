# 학원 파일럿 테스트 플랜

> Phase 19 — 실제 학원 파일럿 도입 전 검증 가이드.
> 작성 시점: 2026-05-20. Supabase write-through + 수동 hydrate 까지 완료된 상태 기준.

---

## 1. 파일럿 목적

이 파일럿은 다음을 검증하기 위한 단계다.

- **중소규모 학원에서 원장 / 강사 / 보조강사가 일상 운영에 실제로 사용 가능한지** 검증
- **같은 계정으로 PC ↔ 모바일** 사이에 학원 데이터를 공유할 수 있는지 검증
- 학생 / 반 / 수업 회차 / 출결 / 수업 기록 / 클리닉 / 수납 / 급여 — **8개 도메인의 전체 흐름** 이 한 번의 하루 운영 시나리오 안에서 모두 동작하는지 검증
- **localStorage(앱) ↔ Supabase(서버) 동기화** 가 새 기기 / 새 세션에서도 정상적으로 복구되는지 검증

이번 파일럿의 목적은 **새 기능 출시가 아니라, 기존 기능이 실제 환경에서도 흔들리지 않는지 점검** 하는 것이다.

---

## 2. 테스트 전 준비

### 2.1 계정 / 환경 준비
1. Supabase 프로젝트가 정상 가동 중인지 확인 (Auth / Table Editor 접근 가능)
2. 테스트용 메일로 회원가입 후 로그인
3. **학원 워크스페이스 생성** — 학원 이름 / 원장 이름 입력
4. PC Chrome / Safari 정상 로딩 확인
5. 모바일 또는 PC 시크릿 창에서 **동일 계정 로그인**
6. 두 번째 기기에서 `더보기 → 학원 워크스페이스 → 서버 데이터 불러오기` 버튼 또는 자동 hydrate 안내 모달 확인

### 2.2 권장 데이터 셋업
- 학생 3~5명 (학년 / 과목 다양하게)
- 반 2개 (각각 학생 2명 이상 배정)
- 강사 1명 / 보조강사 1명
- 1주일치 수업 회차

## 3. 원장 역할 테스트

> `더보기 → 역할 변경 → 원장` 로 전환한 뒤 진행.

| # | 시나리오 | 확인 포인트 |
|---|---|---|
| 3-1 | 학생 추가 | 이름 / 학년 / 과목 / 연락처 입력 → 저장 → 학생 목록에 즉시 표시 |
| 3-2 | 학생 수정 / 삭제 | 수정한 값이 상세 페이지에 반영, 삭제 후 목록에서 사라짐 |
| 3-3 | 반 만들기 | 반 이름 / 담당 강사 / 학생 선택 / 요일·시간 입력 → 저장 |
| 3-4 | 반 수정 | 학생 추가·제거, 시간 변경이 반영됨 |
| 3-5 | 반 삭제 | 반 / 수업 회차 / 출결 / 수업기록이 함께 정리되는지 확인 |
| 3-6 | 수업 회차 자동 생성 | 반 생성 시 향후 4~8주 회차가 자동 생성됨 |
| 3-7 | 수업 회차 추가 / 수정 / 삭제 | 단일 회차 단위 편집이 가능 |
| 3-8 | 정산 탭 — 수납 추가 | 학생 선택 / 금액 / 월 입력 → 저장 |
| 3-9 | 정산 탭 — 납부 완료 토글 | `미납 ↔ 완료` 변경, 통계 즉시 반영 |
| 3-10 | 정산 탭 — 월별 자동 생성 | 한 달치 수강료 행이 일괄 생성됨 |
| 3-11 | 정산 탭 — 강사 급여 자동 생성 | 시급 / 월급 강사 각각 행이 정상 계산됨 |
| 3-12 | 더보기 → 학원 워크스페이스 | 8개 테이블 카운트가 표시됨 |

### 3.x 원장 시점에서 반드시 확인
- 통계가 모순 없는 값을 보이는지 (예: 미납 금액 + 완납 금액 = 총액)
- 한 학원 안에서 모든 도메인이 같은 학원 ID 로 묶여 있는지

## 4. 강사 역할 테스트

> `더보기 → 역할 변경 → 강사` 로 전환.

| # | 시나리오 | 확인 포인트 |
|---|---|---|
| 4-1 | 담당 수업 확인 | 본인이 담당인 반만 표시 |
| 4-2 | 수업 회차 진입 | 오늘 / 가까운 회차가 강조되는지 |
| 4-3 | 출결 체크 | 학생별 출석 / 결석 / 지각 / 사유결석 표시 |
| 4-4 | 공통 진도 작성 | 회차 단위 공통 메모 저장 |
| 4-5 | 학생별 태도 / 집중도 / 이해도 | 5단계 입력 후 저장 |
| 4-6 | 학습 보완 항목 입력 | 태그 + 메모 입력, 클리닉 연계 마커 표시 |
| 4-7 | 수업 기록 저장 | 저장 후 회차 목록에서 “기록됨” 표시 |
| 4-8 | 서버 저장 확인 | Supabase `lesson_records`, `attendance_records` 행 생성 |

### 4.x 강사 시점에서 반드시 확인
- 출결 체크 안 한 학생도 `present` 기본값으로 서버 행이 생성되는지
- 학습 보완 항목이 보조강사 클리닉 탭에 노출되는지

## 5. 보조강사 역할 테스트

> `더보기 → 역할 변경 → 보조강사` 로 전환.

| # | 시나리오 | 확인 포인트 |
|---|---|---|
| 5-1 | 클리닉 탭 진입 | 학습 보완 항목 기반 “필요” 목록 표시 |
| 5-2 | 클리닉 기록 추가 | 학생 / 반 / 회차 매핑 후 저장 |
| 5-3 | 학습 보완 항목 → 클리닉 흐름 | 강사가 입력한 보완 태그/메모가 모달 초기값으로 들어옴 |
| 5-4 | 클리닉 수정 / 삭제 | 변경 / 삭제 후 목록 즉시 반영 |
| 5-5 | 서버 저장 확인 | Supabase `clinic_records` 행 생성 |

### 5.x 보조강사 시점에서 반드시 확인
- 본인이 담당이 아닌 반의 학생 클리닉도 작성 가능한지 (학원 내 공유 권한)
- `source_support_tags`, `source_support_memo` 값이 서버에 함께 저장되는지

## 6. PC ↔ 모바일 연동 테스트

### 6.1 PC → 모바일
1. PC 에서 학생 / 반 / 수업 기록 / 수납 추가
2. 모바일에서 같은 계정 로그인 (이전에 안 썼다면 새로 회원가입)
3. 안내 모달의 `서버 데이터 불러오기` 또는 `더보기 → 학원 워크스페이스` 의 수동 버튼 클릭
4. 학생 / 반 / 수업 / 수납이 동일하게 표시되는지 확인

### 6.2 모바일 → PC
1. 모바일에서 출결 체크 / 수업 기록 / 클리닉 작성
2. PC에서 `더보기 → 학원 워크스페이스 → 서버 데이터 불러오기` 클릭
3. 모바일에서 작성한 기록이 PC에 그대로 반영되는지 확인

### 6.3 동일 기기 다른 브라우저
- PC 일반 창 ↔ 시크릿 창에서 동일하게 hydrate 가능한지 확인

> **주의**: 자동 실시간 동기화가 아니므로, 다른 기기의 변경사항을 보려면 명시적으로 “서버 데이터 불러오기” 를 실행해야 한다.

## 7. Supabase Table Editor 확인 항목

각 도메인의 행이 정상 생성되는지 Table Editor 에서 확인한다.

| 테이블 | 확인 컬럼 |
|---|---|
| `students` | `name`, `grade`, `subjects`, `academy_id`, `mode='academy'` |
| `class_groups` | `name`, `subject`, `teacher_name`, `students` (jsonb) |
| `class_sessions` | `date`, `start_time`, `end_time`, `class_group_id` |
| `lesson_records` | `class_session_id` (unique), `common_record`, `student_records` (jsonb) |
| `attendance_records` | `class_session_id`, `student_id`, `status`, `(class_session_id, student_id)` unique |
| `clinic_records` | `student_id`, `date`, `source_support_tags`, `source_support_memo` |
| `payments` | `student_id`, `month`, `amount`, `paid`, `paid_at` |
| `payrolls` | `staff_type`, `staff_id`, `month`, `amount`, `paid` |

각 테이블에서 다음을 확인한다.
- `mode` 가 모두 `academy` 인지
- `academy_id` 가 현재 학원의 id 와 일치하는지
- `user_id` 가 작업자 본인 (RLS 기준) 인지

## 8. 알려진 한계 및 주의사항

> 파일럿 진행 중 마주칠 수 있는 제약사항.

- **localStorage 가 여전히 source of truth.** 서버는 보조 미러. 새 기기 hydrate 는 수동 트리거 필요
- **실시간 동기화 없음.** 두 기기가 동시에 같은 데이터를 수정하면 마지막 hydrate 가 덮어쓴다 (충돌 해결 미구현)
- **강사 / 보조강사 초대 / 권한 세분화 미구현.** 현재는 같은 학원 계정을 공유하거나, 원장이 역할만 바꿔서 테스트하는 구조
- **서버 측 `staff` 테이블 없음.** 강사 / 보조강사 정보는 localStorage 만 존재. 급여(payrolls) 의 `staff_id` 는 로컬 id 를 그대로 사용
- **`payments.class_group_id` null 허용.** unique 제약이 NULL 다중 허용이므로 같은 학생-월 행이 중복 생성될 수 있음 (현재는 클라이언트 dedupe 로 회피)
- **반 수정 시 기존 수업 회차 재생성 동기화 제한적.** 시간 변경은 신규 회차에만 반영, 과거 회차는 그대로 유지
- **`lesson_records` 의 `source_lesson_record_id` 항상 null.** 로컬 기록에 serverId 가 없어 매핑이 불가 — 클리닉의 출처 추적이 약한 상태
- **hydrate 정책: serverWins + preserveLocalOnly.** 서버에 있는 데이터는 서버 값으로 덮어쓰고, 로컬에만 있는 항목은 유지

## 9. 파일럿 성공 기준

다음 항목이 모두 큰 문제 없이 통과되면 파일럿 성공으로 간주한다.

- ✅ 원장이 PC 에서 학생 / 반 / 수납 / 급여 관리를 끊김 없이 수행할 수 있다
- ✅ 강사가 모바일 또는 PC 에서 수업 기록 / 출결 / 학습 보완 입력을 끊김 없이 수행할 수 있다
- ✅ 보조강사가 클리닉 기록을 끊김 없이 작성하고 학습 보완 흐름을 연계할 수 있다
- ✅ 새 기기에서 “서버 데이터 불러오기” 만으로 학원 데이터가 복원된다
- ✅ Supabase Table Editor 에서 8개 도메인 테이블에 정상적으로 행이 적재된다
- ✅ 하루 운영 시나리오를 처음부터 끝까지 통과하는 동안 치명적 오류가 발생하지 않는다

## 11. 문제 발생 시 대응

- **에러 토스트가 떴는데 화면은 정상**: localStorage 는 저장된 상태. Supabase 만 실패한 경우다. `더보기 → 학원 워크스페이스` 에서 카운트가 일치하는지 확인 → 일치하지 않으면 다시 같은 동작을 시도해 서버 재기록을 유도한다.
- **로컬은 비었는데 서버에는 데이터가 있는 새 기기**: 안내 모달에서 `서버 데이터 불러오기` 클릭. 모달이 뜨지 않으면 `더보기 → 학원 워크스페이스 → Hydrate 버튼` 사용.
- **서버 데이터를 통째로 잘못 덮어썼을 때**: 현재는 자동 복구 수단 없음. 단일 기기에서 작업하던 마지막 localStorage 가 백업 역할을 함.
- **두 기기에서 동시에 수정 후 데이터가 어긋난 경우**: 마지막 hydrate 기준으로 일치. 충돌 해결은 후속 단계에서 다룰 영역.
