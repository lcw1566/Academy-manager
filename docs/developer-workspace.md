# 개발자 워크스페이스 운영 가이드

개발자 워크스페이스 등록에 로그인 비밀번호는 사용하지 않는다. 기존 Supabase Auth
계정의 사용자 UUID만 서버 측 허용 목록에 등록한다.

## 최초 설정

1. `supabase/sql/078_developer_workspace.sql`을 운영 Supabase에 적용한다.
2. Supabase Dashboard의 **Authentication → Users**에서 개발자 계정의 UUID를 복사한다.
3. 로컬 환경에서 다음 명령을 실행한다.

```bash
npm run developer:access -- grant <사용자-UUID> developer
```

`.env.local`의 `SUPABASE_SECRET_KEY`는 서버 운영 명령에만 사용하며 `VITE_` 접두사를
붙이거나 브라우저 코드에 넣지 않는다. 비밀번호, 세션 토큰, 복구 코드는 공유하지 않는다.

권한을 해제할 때는 다음 명령을 사용한다.

```bash
npm run developer:access -- revoke <사용자-UUID>
```

등록 또는 해제 후 앱에서 로그아웃했다가 다시 로그인한다. 권한이 확인된 계정의
워크스페이스 선택 화면에만 **개발자 워크스페이스** 카드가 표시된다.

## 제공 범위

- 버그 신고와 개선 제안 목록
- 접수/검토 중/개선 예정/해결/종료 상태 변경
- 신고 첨부 이미지의 짧은 만료시간 서명 URL
- 활성 학원 및 활성 구성원 수의 익명 집계
- 개발자가 수행한 상태 변경 감사 로그

학생·학부모 연락처, 체크인 PIN, 학원 원본 데이터, 임의 계정 가장 기능은 제공하지
않는다. 지원 목적으로 실제 학원 접근이 필요해지면 원장 동의, 만료시간, 최소 권한,
접근 로그를 갖춘 별도 지원 세션 기능으로 설계한다.

## 개발 환경 분리

운영 상태를 보는 개발자 워크스페이스와 신규 기능을 시험하는 개발 버전은 분리한다.
새 기능과 데이터 변경 시험에는 별도의 staging 배포와 staging Supabase 프로젝트를
사용하며, 운영 학생·수납·급여 데이터를 테스트 데이터로 복제하지 않는다.

자동 E2E는 운영 개발자 워크스페이스가 아니라 로컬 Supabase에서만 실행한다. 테스트
계정 준비, RLS 검증, Playwright 실행 방법은 `docs/e2e-testing.md`를 따른다. 저장소의
E2E 실행기는 원격 Supabase URL을 감지하면 테스트를 중단한다.

로컬 합성 테스트 학원의 활성 구성원은 역할별 독립 계정 검증을 위해 테스트 학원 문맥을
공유한다. 테스트 학원 등록부를 직접 조회할 수는 없으며, 활성 개발자가 등록한 학원의
활성 멤버십을 서버 RPC가 모두 확인한 경우에만 잠긴 테스트 기능이 열린다. 환경별 경계와
운영 테스트 계정 정책은 `docs/testing-strategy.md`를 따른다.
