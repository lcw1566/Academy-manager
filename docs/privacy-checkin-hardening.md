# 개인 과외 제거와 개인정보·공개 체크인 보강

## 적용 범위

개인 과외 진입 카드, 전용 화면과 스토어 액션, 로컬 Gemini API 키와 AI 알림장 호출을
제거했다. 기존 `tutor` 프로필도 학원 선택/초대 흐름으로 진입한다. 학원 권한은 활성
멤버십으로 결정하며, 과거 프로필 값을 학원 소유자 권한으로 자동 승격하지 않는다.
`20260914164501_retire_private_workspace.sql`은 10개 공유 테이블에서 개인 과외 행을
삭제하고 `mode='academy'` 제약조건으로 재생성을 차단한다. 개인 과외 학생 조회 RPC도
제거한다. 학원 소유 정보나 학원 측 종속 행이 연결돼 있으면 전체 변경을 중단한다.
로그인 계정·프로필·학원 멤버십은 함께 사용하는 신원 정보이므로 삭제하지 않는다.

브라우저 `academy-store`는 읽기·쓰기·rehydration 시 허용 목록으로 정리한다.
기존 개인 과외 데이터 및 키, 학생 목록 전체를 영구 캐시에서 제거한다.
로그인한 사용자는 보안 RPC로 학생을 다시 불러온다. 이전 탭은 배포 후 새로고침해야
새 코드가 적용되며, 접속하지 않은 기기의 저장소를 서버에서 원격 삭제할 수는 없다.
수납·수업·직원 등 다른 학원 캐시까지 모두 제거한 변경은 아니다.

## 공개 학생 QR

`20260914085853_secure_public_checkin.sql`은 서버 발급 토큰과 PIN 실패 횟수 테이블을
추가한다. 두 테이블 모두 RLS를 켜고 직접 조회/변경 권한을 주지 않는다.
`issue_academy_checkin_qr`은 해당 학원의 활성 원장 또는 출결 수정 권한이 있는 직원만
호출할 수 있다. 발급 토큰은 20초 구간별로 공유하며 최대 40초 유효하다.

`public_student_checkin`은 DB의 발급 기록, 학원, 현재 QR 설정, 폐기 기준 토큰과
만료 시각을 확인한다. 만료 인자를 생략하거나 미래로 변조해도 연장되지 않는다.
같은 학원에서 PIN 입력이 5분간 30회 실패하면 해당 구간 동안 공개 체크인을 차단한다.
토큰 갱신으로 이 제한을 초기화할 수 없다. 제한에는 PIN·학생 신원·IP를 기록하지 않는다.
학원 전체 제한이므로 다수의 오입력이나 공격 시 정상 학생도 잠시 차단될 수 있다.
이 경우 권한 있는 직원이 수동으로 출결을 처리한다.

학생 카드 스캔과 인증된 직원 출퇴근 RPC는 후속
`20260918023454_harden_authenticated_attendance_paths.sql`과
`20260922111755_enforce_staff_attendance_method.sql`,
`20260922113011_prevent_rapid_staff_qr_checkout.sql`에서 별도 보강했다.
인증 사용자의 학생 등하원·직원 근퇴 직접 테이블 변경을 닫고, 학생 수동 누락 기록은
학원·학생·시각을 검증하는 RPC로 옮겼다. 직원 QR은 서버 발급 토큰과 서버 시각을
검증하며 일반 직원이 QR 설정을 수동 RPC로 우회할 수 없다. SQL 093은 역할별 직접
테이블·RPC 요청, 다른 학원/비활성 대상, 위조 시각, 즉시 재요청을 검증한다.
이 변경은 로컬에서만 검증됐으며 스테이징·운영 반영 전이다.

## 배포 순서

1. 로컬에 migration을 적용하고 DB 역할 테스트, E2E, production build를 통과시킨다.
2. 스테이징 DB dry-run에서 대상과 pending 파일을 확인한 뒤 migration을 적용한다.
3. 같은 변경의 스테이징 앱을 배포하고 실제 배포에서 E2E 및 QR을 검증한다.
4. 운영 배포 시 dry-run으로 대상과 migration을 다시 확인하고, DB 다음 앱 순서로 적용한다.
   운영 스키마 적용은 명시적으로 승인된 배포 작업에서만 실행한다.
5. 기존 QR 표시 창을 새로고침하고 새 QR의 정상 체크인, 변조 거절, 즉시 오류 로그를 확인한다.
   migration 이력과 Supabase Advisors도 확인한다.

DB 적용 즉시 기존 정적 QR은 거절된다. DB와 앱 사이의 전환 시간에는 수동 출결을 사용한다.
앱만 이전 버전으로 롤백하면 정적 QR은 계속 거절되므로 구버전 QR을 다시 허용하는 SQL을
적용하지 않는다. QR 문제가 생기면 수동 출결을 유지하며 새 앱을 수정 배포한다.

## 회귀 검증

- `check:privacy-cache`: 구버전·현재·미래 버전 envelope와 깨진 캐시 정리.
- SQL 088: 원장·매니저·선생님·위임 직원·초대 대기·비활성·비회원·비인증 발급 권한,
  만료·인자 변조·학원 변경·토큰 폐기·PIN 제한과 시간 경과 후 복구.
- SQL 089: 실제 삭제 migration을 합성 데이터에 실행해 학원 행 보존, 연결된 학원
  데이터가 있을 때 중단, 개인 과외 재생성 차단, 재실행 안전성을 검증하고 롤백.
- Playwright: 실제 REST/RPC 거절과 정상 체크인, 학생 캐시 정리와 재조회,
  밝은/어두운 테마 및 동작 감소 설정의 공용 QR·만료 안내.

로컬 통과와 운영/스테이징 반영은 별개다. 배포 결과는 배포한 커밋과 환경에서 확인한다.
