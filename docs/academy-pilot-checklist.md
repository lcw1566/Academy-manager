# 학원 파일럿 도입 체크리스트

> 실제 학원에서 첫 데이터를 입력하기 전 한 번에 확인하는 체크리스트.
> 상세 시나리오는 [pilot-qa-checklist.md](./pilot-qa-checklist.md) 와
> [academy-pilot-test-plan.md](./academy-pilot-test-plan.md) 참고.

---

## 1. 사전 준비

### 1.1 Supabase
- [ ] [`supabase-final-migration-checklist.md`](./supabase-final-migration-checklist.md) 의 001 ~ 008 모두 실행 완료
- [ ] 마지막 한 줄 확인 SQL (`tables=16, functions=6`) 통과
- [ ] 프로젝트 anon key 가 클라이언트 환경 변수에 들어 있음 (`VITE_SUPABASE_ANON_KEY`)
- [ ] **service_role 키는 어디에도 노출되어 있지 않음** (env / git history / 빌드 산출물 모두 확인)

### 1.2 배포
- [ ] `npm run build` 통과
- [ ] 배포된 URL 에서 정상 로딩 (콘솔 에러 없음)
- [ ] PC + 모바일에서 같은 URL 접속 가능

### 1.3 학원 측 안내
- [ ] 원장에게 이 체크리스트와 "알려진 한계" 섹션 공유
- [ ] 데이터 입력은 **테스트 1주 후** 본 데이터로 진행한다는 합의
- [ ] 문제 발생 시 연락 채널 합의

## 2. 만들어야 할 계정

총 4개. 모두 서로 다른 이메일로 가입.

| 역할 | 이메일 (예시) | 가입 시 계정 유형 |
| --- | --- | --- |
| 원장 | owner@pilot-academy.com | 학원 원장 |
| 강사 | teacher@pilot-academy.com | 강사 |
| 보조강사 | assistant@pilot-academy.com | 보조강사 |
| 과외 | tutor@pilot-academy.com | 과외 선생님 |

가입 시 **이름 / 연락처** 필드를 모두 입력하도록 안내 (StaffInviteWidget 이 이메일로 매칭).

## 3. 준비할 테스트 데이터

원장 계정으로 미리 만들어두면 데모가 부드러워집니다.

### 3.1 학원 / 멤버
- [ ] 학원 1개 생성 (`OO학원`)
- [ ] 강사 1명 초대 → 강사 계정이 받은 초대 수락
- [ ] 보조강사 1명 초대 → 보조강사 계정이 받은 초대 수락
- [ ] 더보기 → 구성원 관리에서 3명이 보이는지 확인

### 3.2 학생
- [ ] 학생 3 ~ 5명 등록 (이름 / 학년 / 학교 / 학부모 연락처)
- [ ] 등원일 = 오늘 자동 입력 확인
- [ ] 학부모 호칭 (어머님/아버님/보호자) 선택 확인

### 3.3 반 / 회차
- [ ] 반 1 ~ 2개 생성
  - 담당 강사 지정
  - 보조강사 옵셔널 (Phase 34 — 비워둬도 정상)
  - 요일 + 시작/종료 시간 + 시작일 입력
- [ ] **반 생성 직후 "근무표도 함께 만들까요?" sheet 노출** 확인
  - "수업 시간만 근무로 추가" 또는 "앞뒤 30분 포함" 선택
  - 토스트에 `근무표 N건 추가` 메시지

### 3.4 근무 / 수업 / 출결 / 기록
- [ ] 근무 탭 → 오늘 강사·보조강사의 근무가 표시됨
- [ ] 회차 상세 페이지 진입 → 학생별 출결 + 수업 기록 저장
- [ ] (보조강사 모드) 클리닉 1건 등록 + 완료 처리

### 3.5 수납 / 급여
- [ ] 정산 탭 → 이번 달 수강료 자동 생성 확인
- [ ] 학생 1명 납부 완료 토글
- [ ] 정산 탭 → 이번 달 급여 명세 자동 생성 (시급제 강사는 근무 합계 시간 반영)
- [ ] 급여 1명 지급 완료 처리

### 3.6 대체 강사
- [ ] 강사 A 가 담당인 회차 → 다른 강사 B 로 대체 지정
- [ ] **B 가 그 시간에 근무가 없으면 "근무 시간이 없어요" sheet 노출** 확인
- [ ] 자동 추가 옵션 선택 → 근무 추가 + 대체 강사 배정 완료
- [ ] B 의 홈에 그 회차가 나타나고, A 의 홈에서는 빠짐

## 4. 데모 흐름 (30분 시연용)

총 6단계, 각 5분.

1. **로그인 → 학원 선택** (1분)
   - 원장 계정 로그인
   - "학원을 선택해주세요" 화면에서 OO학원 카드 탭

2. **학생/반 만들기** (5분)
   - 학생 1명 추가
   - 반 1개 생성 (강사 + 보조강사)
   - 근무표 자동 추가 sheet 에서 추천 옵션 선택

3. **수업 진행** (8분)
   - 강사 계정으로 전환 (다른 기기 또는 시크릿)
   - 홈 → "오늘 근무" 출근 버튼
   - 오늘 회차 진입 → 출결 + 수업 기록 저장 → 수업 완료

4. **보조강사 클리닉** (3분)
   - 보조강사 계정으로 전환
   - 클리닉 탭 → 학생 클리닉 1건 작성 → 완료

5. **정산 / 급여** (8분)
   - 원장 계정으로 돌아옴
   - 정산 탭 → 수강료 자동 생성 → 1명 납부 완료
   - 정산 탭 → 급여 명세 생성 → 지급 완료
   - 시급제 강사의 급여 = 근무 시간 × 시급 확인

6. **다른 기기 동기화** (5분)
   - 모바일 시크릿 창에서 강사 계정 로그인
   - 자동 hydrate 후 같은 출결/기록/근무 보이는지 확인
   - 모바일에서 출결 1건 수정 → PC 새로고침 → 변경 반영 확인

## 5. 알려진 한계 (Pilot 시점)

### 5.1 동기화
- **로컬 우선**: 모든 편집은 로컬에 먼저 적용되고 서버에 비동기로 전송됩니다.
  서버 실패 시에도 로컬 변경은 유지되며 토스트로만 안내됩니다.
- **다른 기기 자동 hydrate**: 로그인 직후 자동으로 서버 데이터를 불러오지만,
  같은 기기에서 다른 기기의 실시간 변경을 자동으로 받아오지는 않습니다.
  필요 시 더보기 → 데이터 관리 → 새로고침 사용.

### 5.2 보조강사
- 반 단위로만 배정 가능. 회차별로 다른 보조강사를 두는 UI 는 미지원 (반 생성 시 모든 회차에 일괄 적용).
- 보조강사가 수업에 배정돼야 작동하는 압박은 없음 — 클리닉이 본 업무.

### 5.3 근무 자동 제안
- 반 생성 직후 **다음 7일 이내** 회차만 근무 자동 추가 대상. 장기간 회차는 owner 가 근무 탭에서 직접 추가.
- 이미 같은 시간에 등록된 근무가 있으면 중복 생성 안 됨 (자동 skip / extend).

### 5.4 급여 계산
- 시급제 default = **학원에 머문 시간 (shift) 기준**. 강사/보조강사 폼에서 "수업 시간만 정산" 옵션 가능.
- 월급제는 근무/수업 시간에 영향받지 않고 매월 동일.
- 보조강사 클리닉 완료 카운트는 **참고용**, 급여 계산에 영향 없음.

### 5.5 삭제·초기화
- 학원 모드에서는 학원/원장 데이터 삭제 UI 가 일반 화면에 노출되지 않습니다 (Phase 34 부터 숨김).
- 과외(tutor) 모드는 본인 로컬 데이터 초기화 버튼이 더보기에 남아 있음 — 본인 책임으로 사용.

### 5.6 보안
- 모든 도메인 데이터는 Supabase RLS 로 분리. 다른 학원 / 다른 사용자의 데이터는 조회/수정 불가.
- 프로필 이메일 검색은 별도 security definer RPC (`search_profile_by_email`) 만 가능. 학원 멤버가 아닌 사용자의 정보는 노출되지 않음.

## 6. 비상 절차

### 6.1 로컬 데이터가 이상할 때 (한 기기 한정)
1. 다른 기기에서는 정상인지 먼저 확인 (서버 데이터는 안전한지 확인).
2. 정상이라면, 이상한 기기에서 브라우저 개발자 도구 → Application → Local Storage → 사이트 항목 삭제.
3. 다시 로그인 → 자동 hydrate 가 서버에서 데이터를 다시 불러옴.

### 6.2 잘못된 회차/학생/근무를 추가했을 때
- 정상 흐름: 해당 화면의 삭제 버튼 사용 (로컬 + 서버 모두 삭제됨).
- 안 되는 경우: 원장 계정으로 더보기 → 데이터 관리 → 새로고침으로 서버 상태 다시 동기화.

### 6.3 학원 전체를 다시 시작해야 할 때 (마지막 수단)
- 권장: 신규 학원을 새로 만들고 그쪽으로 진행.
- 정말 같은 학원에서 재시작해야 한다면, Supabase Dashboard 에서 해당 academy_id 에 속하는 row 를 수동 삭제 후 앱 새로고침. (앱 UI 에서는 학원 전체 초기화를 제공하지 않음.)

### 6.4 Supabase 가 응답하지 않을 때
- 앱은 로컬 우선으로 동작하므로 **편집/조회는 계속 가능**.
- 새 데이터는 로컬에만 저장되며, Supabase 가 복구되면 다음 작업 시 write-through 가 다시 시도됨.
- 단, **새 계정 로그인 / 학원 전환** 은 Supabase 가 필요. 이때만 차단됨.

## 7. 첫 주 모니터링 항목

원장이 매일 한 번씩 가볍게 확인:

- [ ] 오늘 출결이 모두 저장됐는지
- [ ] 수업 기록이 누락된 회차가 있는지 (홈 카드에 미작성 알림)
- [ ] 근무 출근/퇴근이 모두 기록됐는지
- [ ] 미납 학생 인원수
- [ ] 어제까지의 토스트 중 "동기화 실패" 메시지 발생 빈도

토스트가 자주 실패한다면, Supabase 대시보드의 logs 에서 RLS 거부 여부를 확인 후 개발자에게 공유.
