# 비공개 파일 저장소 보호

`academy-drive`와 `feedback-attachments`는 공개 URL로 원본 파일을 제공하지 않는
비공개 버킷이다. 버킷 생성과 제한은
`20260923153742_enforce_private_storage_buckets.sql`에서 관리하므로 새 로컬·스테이징·운영
환경도 같은 설정을 재현한다.

| 버킷 | 제한 | 직접 접근 규칙 |
|---|---|---|
| `academy-drive` | 파일당 50 MiB, 비공개 | 활성 구성원은 자신이 먼저 등록한 메타데이터 경로에만 업로드한다. 원장만 Storage 원본을 직접 조회하며, 일반 직원은 현재 멤버십과 다운로드 정책을 다시 확인하는 `academy-drive-file`의 60초 URL을 사용한다. |
| `feedback-attachments` | 파일당 5 MiB, JPG·PNG·WEBP, 비공개 | 신고자는 자신의 사용자 ID로 시작하는 경로만 업로드·조회·삭제한다. 서버 허용 목록에 등록된 개발자는 접수 처리 목적으로 조회할 수 있다. |

`supabase/tests/094_private_storage_access.sql`은 원장·매니저·선생님·위임 직원·초대
대기·비활성 직원·다른 학원 원장·외부인·비로그인 요청을 직접 RLS로 검증한다.
`tests/integration/storageAccess.test.mjs`는 로컬 Storage HTTP API에서 실제 바이트를
업로드하고 다음을 확인한다.

- 같은 학원 원장은 파일을 내려받을 수 있다.
- 일반 직원은 업로드할 수 있지만 Storage를 직접 우회해 내려받을 수 없다.
- 다른 학원 계정과 비로그인 요청은 파일을 받을 수 없다.
- 공개 URL 요청은 성공하지 않는다.
- 신고 이미지는 소유자만 읽고 삭제할 수 있으며 허용하지 않은 MIME은 거절된다.
- 드라이브 데이터가 있는 학원도 감사 트리거 충돌 없이 정상 삭제된다.

운영 파일이나 고객 개인정보를 자동 테스트에 사용하지 않는다. 배포 전에는 스테이징
합성 파일로 업로드·열람·다운로드 제한을 확인하고, 운영에서는 읽기 중심의 최소 스모크만
수행한다. Storage 객체는 Supabase DB 백업에 포함되지 않으므로 별도 백업 절차가 필요하다.
